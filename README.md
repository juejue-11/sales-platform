# 采购阅读与跟进工作台

2026-10-16：信息采集已接入同一平台。打开“信息采集”可查看来源、启停来源、执行全部或单来源采集，并调整每日自动采集时间；手动采集结束后自动导入，再沿用既有采购阅读、研判和跟进流程。采集与筛选仍是两个独立模块，原目录、数据库、证据归档和 JSONL 交接方式保留。部署及异常处理见 [统一平台采集管理](docs/collection-integration.md)。

2026-10-14 新构思已接入开发：采购需求列表、独立 AI 采购说明与来源、AI 研判、用户跟进任务和材料。模块职责、资料边界及运行条件见 [采购工作台实现说明](docs/procurement-workbench.md)。采购事实和真实跟进记录分别保存；重新生成研判不会覆盖已完成动作与提交记录。

面向矿山设备采购的本地网页平台。

流程：采集端按时效和设备采购范围筛选 → 采购资料接入并阅读 → 浏览与筛选采购需求 → AI 研判 → 用户采用计划并记录实际跟进。

当前采集仅保留近 30 天发布、未明确超过投标／报价截止时间的设备整机及备件采购；缺失发布日期、新闻、矿业权和非设备采购不进入新采集记录。历史不符合记录已于 2026-10-17 清理，保留项目的阅读、分析和跟进状态不变。日常使用与开发入口见下文，历史恢复点统一存放于工作区 `归档/`。

默认面向矿山设备经销商和生产商分析需求、项目机会、参与条件及下一步。企业资料可选，提供后再增强企业匹配；关注关键词、地区和公司名称不证明产品或投标能力。

## 打开平台

双击本目录的 `启动平台.cmd` 即可启动并打开网页。也可以运行：

```powershell
powershell -ExecutionPolicy Bypass -File .\启动平台.ps1 -OpenBrowser
```

地址：<http://127.0.0.1:8766>。再次运行启动脚本会复用已启动的平台。

双击 `停止平台.cmd` 或运行以下命令停止服务：

```powershell
powershell -ExecutionPolicy Bypass -File .\停止平台.ps1
```

初次安装或代码更新后，可运行 `安装依赖.ps1`。本机已提供独立Python环境；安装脚本支持Codex自带运行时，其他机器需Python、Node.js 22.19或更新版本与pnpm。安装脚本同时构建Pi SDK分析组件与前端。

## 首次使用

1. 在“采购需求”查看真实项目，按设备或服务、地区、采购单位、采购阶段和关键时间筛选。明确采购与潜在线索分别标识。
   需要更新资料时，在“信息采集”查看当前来源并执行采集；任务同时显示采集结果与导入结果。来源受限或部分失败会保留提示，已取得的资料仍可导入。
2. 在“业务配置”按需填写角色、设备类别、地区、矿种和新建/技改/备件关注方向。企业产品、能力和案例是可选增强资料，留空仍能分析市场。明确排除项用于规则初筛；未知能力保留为待核实。
3. 填写兼容OpenAI的接口地址（例如服务商提供的 `/v1` 地址）、模型和API密钥，开启AI。模型及接口需支持流式Chat Completions和工具调用。Pi SDK按需读取项目原文、关联资料与公司能力，并生成JSON判断和方案；密钥仅在后端保存，页面不会读回密钥。首次启用后，符合条件的项目自动排队分析。
4. 在“处理状态”确认导入成功、来源覆盖和AI任务进展，可重试失败任务。
5. 在“跟进”选择参与方向、负责人和下一步，经采用后生成任务与材料清单。跳过或调整任务填写理由；外部提交需要记录实际时间及渠道。建议关注不等于企业资质通过。

缺少模型时平台显示“模型未配置”，保留初筛与人工处理；不会用样例方案冒充AI结果。缺少企业资料时市场分析正常生成，企业匹配标为未评估；资料存在也不代表已外部核验或资格通过。

## Pi SDK分析

`agent-runtime/`将Pi SDK嵌入专用的TypeScript分析组件。Python任务队列通过子进程管道传入配置和资料，每次分析独立创建内存会话；无需另开Agent服务。密钥不放进命令行参数。

Agent可以查询项目原文、公司能力、关联公告，并按需读取当前公告的公开采购附件。详情页显示实际查询活动，规则初筛、引用校验、人工选择和历史记录由平台管理。附件工具按可信记录编号调用，由后端下载并解析同来源的公开文件，保留文件哈希和引用依据。

Agent 也可以围绕影响结论的问题搜索新的项目资料，读取来源页面或发现的文件，核实同一采购、相关项目或主体背景关系后再引用。“AI 研判”内可展开调查依据；历史调查单独保留。搜索命中不代表确认采购；其他标段和背景资料不证明本次设备需求。

Agent 报告按项目自选章节、段落、列表和表格，逐项区分明确需求与潜在线索，并展示依据、推断关系、待确认内容及行动。没有可确认设备机会时可以不生成机会。缺口区分原文未说明、尚未读取、读取失败和不适用；前端不以附件状态替代整份报告。设备关键词仅表示涉及设备词，采购范围由采集端独立判断。

长附件先返回目录，再按文档编号、页码或关键词读取连续片段；默认每次 8000、最多 16000 字符。同一任务复用已下载的资料，引用仅接受本次实际读取的片段。采集归档经记录目录边界与 SHA-256 核对后可直接复用；在线读取失败时保留此前成功快照并显示失败尝试。附件引用提供保存快照和在线原文两个入口，历史快照不会被一次失败覆盖。

调查引用可打开报告使用的保存快照，在线原文另设入口；来源变化或失效不会覆盖历史证据。重新分析时保留旧报告，当前运行进度与旧报告的调查记录分开展示。来源读取失败或预算停止只限制相关结论，不清空已知事实。

公开调查来源在 `backend/research_sources.json` 配置，可用 `SCREENING_RESEARCH_SOURCES` 指定另一份同结构来源文件。检索仅覆盖已登记、允许访问的官方来源及明确的分页范围；无结果、站点阻断和未配置分别记录。默认工具权限、下载边界、结果限量和预算在后端执行，模型不能提交任意 URL 或扩大来源范围。显式 `single_call` 只分析已有资料，页面标记未执行主动补查。

采购信息页先展示独立保存的 AI 采购说明，保留分项要求、例外、包号、引用、阅读范围和未解决事项。未生成说明时展示可核对的已有资料，不用空白概要表示完成。原结构化物料和事实继续提供完整表格及来源；相同事实合并保留来源，冲突数量不相加，不推測规格或材质。正文引用在阅读抽屉内定位，附件使用保存快照及实际页码核对。

“原始资料”列出公告正文、附件、在线来源和归档下载。正文默认短预览，完整正文在独立阅读抽屉中搜索与定位；阅读视图整理碎片换行，原始文本保留。登录或购买文件保留获取条件；操作失败在处理状态查看。采购说明由 AI 阅读生成并通过程序校验，研判使用它和原始依据；已有规则提取仅用于兼容资料展示。

Agent读取采购附件时，旧版 `.doc` 自动在后台转换为 PDF，再提取正文、表格和页码；`.docx` 直接提取文字与表格。已有项目可点击“检查公开附件”或“更新公开资料”单独补查，无需调用模型；新增资料会保留原分析，内容变化时标记待复核。无法下载、加密或损坏文件、扫描 PDF 等缺口会明确显示，不会标成完整资料。

默认调查来源包括中国煤科官方 GET 搜索、鞍钢官方搜索与酒钢有限列表扫描。搜索记录写明实际检查的平台以及未覆盖的原公告平台；无结果仅代表这些检查范围。使用公告编号或核心设备名称等短查询更便于核对官方结果；候选页面仍须独立读取、核实关系才能作为采购证据。

`安装依赖.ps1` 自动准备 LibreOffice 文档转换组件，也可独立运行 `安装文档转换器.ps1`。转换使用独立临时配置，不显示窗口、不改动原文件，引用哈希仍对应原附件；页码来自转换后的排版。转换单次限时90秒、附件批次限时180秒；文件最多12MiB、80页。Linux部署需安装LibreOffice；自定义安装位置可用 `LIBREOFFICE_PATH` 指定启动器路径。

默认每次SDK执行最多6轮模型调用、12次工具调用、300秒，向模型请求的单次输出预算为16384 tokens（包含思考与最终答案），并在本地限制整次执行的文本输出不超过256 KiB；无效结果最多再生成一次。采购预读关闭思考，支持思考的模型在市场研判任务使用低档思考；DeepSeek 官方预读请求显式禁用 thinking。输出截断单独提示达到token上限，不保存或展示半截方案。异常会显示为失败任务，可以修复后重试。设置`SCREENING_AI_ENGINE=single_call`可显式使用原来的单次调用路径，平台不会在SDK失败时自动切换。

## 数据与更新

- 默认读取旁边采集系统的 `data/export/records.jsonl`，在配置页可更改路径和检查频率。
- 运行期间自动检查文件更新；全量重复导入不重复创建项目。
- 首页显示采集文件更新时间、来源覆盖与试运行缺口；文件超过48小时未更新会提示。最近导入时间另在“处理状态”展示。
- 正文、重要公告字段或业务配置变化后，旧判断标记待复核；人工决定和历史判断保留。
- 市场分析采用 `market_agent_v2` 语义版本，动态报告采用 `report.version=1` 结构协议。升级后旧判断保留并标为待复核；可在处理状态批量分析或详情重新分析，迁移本身不启动付费模型批次。新分析不会继承旧的方案选择。
- 确认重复与同项目公告可关联；疑似重复提示需要人确认。
- 页面提供原文链接与归档下载；采集系统数据保持只读。
- 本平台数据、设置、密钥及日志在 `data/`，该目录不进入Git。
- `data/` 仅保留主数据库及 SQLite 伴随文件、`service.json` 与服务日志、`ai-traces/` 近期诊断和 `backups/` 业务恢复点。验收截图、测试数据库及一次性排查产物统一写入 `tmp/qa/`。
- 电脑关机后服务停止；重新运行启动脚本恢复，后台任务在服务运行时执行。

## 开发

```powershell
.\.venv\Scripts\python.exe -m uvicorn backend.main:app --host 127.0.0.1 --port 8766
```

前端在 `frontend/`，执行 `pnpm dev`。开发代理接口到8766；生产执行 `pnpm build` 后由FastAPI同源提供页面。

后端验证：

```powershell
.\.venv\Scripts\python.exe -m pip install -r requirements-dev.txt
.\.venv\Scripts\python.exe -m pytest backend/tests -q
```

接口约定见 `API_CONTRACT.md`。平台默认用于本机内部决策；面向采购客户的发布页面按后续业务范围增加。

可复用的浏览器和隔离 HTTP 验收工具统一放在 [`tools/qa/`](tools/qa/README.md)。截图与临时验收数据库输出到 `tmp/qa/`；旧 `qa/` 目录中的一次性调试脚本已清理。
