# 采购阅读与跟进工作台

平台入口是已接入来源的采购需求列表，详情分为采购信息、AI 研判、跟进。企业资料与关注偏好在业务配置填写，空资料不阻止浏览或市场研判。

## 职责与依赖

- 采集系统维护来源、抓取、去重和版本，输出 `records.jsonl`。筛选系统只读导入，不写采集数据库或归档。
- `procurement/reading.py` 接收有版本的本次采购资料包，负责切分、采购阅读协议、引用与关键事实校验、结果归并。它不连接数据库、不执行网络请求。
- `application/reading.py` 负责调用已选定的模型 adapter，输出经过校验的采购说明。说明先保存，市场研判再使用它；缺少模型配置时不生成模拟说明。
- `procurement/milestones.py` 统一选择有来源且无冲突的提交时间，供初筛、提醒、排序和筛选使用；不能将获取文件的日期作为提交截止。
- `procurement/dates.py` 按完整日期与时间校验节点，兼容中文日期、碎片换行、单数字小时和 ISO 格式，防止跨区间拼接日期与小时。`procurement/schedule.py` 从当前公告明确标注的时间条款恢复遗漏节点，保留连续原文；历史说明无需再次调用模型，读取时补足节点，不改写历史记录。
- `followup/` 负责用户进度、计划采用、任务、材料和事件留痕。资料更新只标记复核，不回退已完成操作或覆盖真实提交记录。
- `procurement/supplements.py` 负责补充文件及人工纠正留痕。文件仅补足已有采购资料，不能用上传动作创建已确认采购。
- `application/workbench.py` 组合用户动作和持久化；`routes/workbench.py` 验证 HTTP 输入。页面展示模块通过 props 获取说明和来源，跟进模块管理自己的编辑状态。

## 资料与事实

采购说明区分明确采购、潜在线索和待确认内容。文件获取、报名、提问、提交、开标分别保存。未取得的付费或登录资料、未读尾部和解析缺口不能算作已完整阅读。引用必须属于本次实际读取的公告或附件版本。

多包要求保持包号。仅介绍其他包不证明本次采购它；更正范围不明确时保留冲突，提醒用户核对。数量、金额、日期和条件校验是程序约束，不能替代对自然语言含义的人工核对。

节点协议明确使用 `at`，日期时间使用带时区的 ISO 8601，只有日期时保留 `YYYY-MM-DD`，不补造时分。恢复只处理采购公告中有完整日期的明确时间条款；每日工作时段、保证金期限、另行通知及新闻历史日期不会作为投标截止。开始与截止分别显示，多个提交日期或已有冲突不自动选择；待处理、失败及已过期资料不通过恢复变成已验证节点。

### 兼容事实与原文追溯

旧 `procurement.items`、交付字段、附件状态、`facts` 和 `briefing` 继续返回，放在采购说明下的“原始资料与完整物料”中查看。规则提取状态 `extracted` 只表示已提取，不能作为人工核实或完整阅读的证明。

事实与物料合并时保留全部来源；不同规格继续分行，冲突数量不相加，不因资格文字不同就直接判定冲突。来源保留 `source_kind`、`record_id` 和原文 `quote`；附件来源还包含 `document_id`、实际页码及版本哈希。接口字段以 [API_CONTRACT.md](../API_CONTRACT.md) 为准。

完整正文通过独立阅读抽屉搜索和定位，展示时可整理碎片换行，后端原文与证据摘录保持原样。附件快照按项目、文档编号和哈希访问；归档下载返回原始文件。找不到引用摘录时显示未定位状态，不将其他位置冒充引用来源。

## 用户动作

跟进阶段为待评估、办理中、已提交、等待结果、已结束，另记录跟进、暂缓或放弃。计划先作为建议展示，经用户采用后成为任务；采用不覆盖既有任务操作。

任务区分来源必办、路径条件和额外建议。跳过任务或调整要求记录理由。材料准备、材料检查与外部提交分别记录；已提交需用户填写实际时间及渠道，可附凭证。AI 结果或任务全部完成都不能自动成为外部提交或资格通过。

补充文件支持 PDF、DOCX、DOC 和 UTF-8 TXT，最多 12 MiB。原始字节和解析状态保存在筛选系统数据库；损坏或扫描文件仍可下载核对。人工纠正记录具体要求（或遗漏）、内容、理由及当时资料版本，后续阅读必须处理这些反馈与来源的关系。

## 运行与验证

开发验证使用临时数据库、Mock 模型和 Mock 浏览器接口，不运行付费模型批次。已有真实数据、设置、密钥和历史保留。

新导入与变更资料自动进入阅读、研判流程。历史数据不会因升级触发付费整库重算；可在处理状态提交待处理项目或针对项目重试。

验证命令：

```powershell
.\.venv\Scripts\python.exe -m pytest backend/tests -q
cd frontend
pnpm run build
cd ../agent-runtime
pnpm run build
pnpm test
```

[`tools/qa/workbench_mock.cjs`](../tools/qa/workbench_mock.cjs) 验证页面及写入契约。`tools/qa/serve_fixture.py` 使用公开 #224 样本、隔离数据库和关闭的模型配置，供 `tools/qa/workbench_api.cjs` 验证真实 HTTP 与浏览器流程。具体命令见[开发验收工具说明](../tools/qa/README.md)，产物统一放在 `tmp/qa/`。

后台自动化依赖采集系统任务及筛选系统运行；关机期间不运行。来源覆盖沿用已登记且能访问的范围。扫描件目前仍需要可读文本或人工补充，不能宣称所有文件均自动解析。真实模型对复杂条款的质量还需按实际来源抽样核对。
