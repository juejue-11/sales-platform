# Agent 框架实现约定

默认任务面向矿山设备市场开发。企业资料可选；客户关注方向调整分析重点，不能替代产品、资质和交付能力证明。采集系统负责持续发现线索，筛选平台负责调查、判断、保存证据和提供人工行动入口。

## 模块职责

| 位置 | 职责 |
| --- | --- |
| `backend/analysis_policy.py` | 平台目标、客户偏好、企业资料的分离及语义版本 |
| `backend/project_research.py` | 受控来源检索、读取、关系核实、资料版本与调查预算 |
| `backend/document_access.py` | 当前项目附件的目录、按页及关键词片段读取，统一返回大小限制 |
| `backend/agent_report.py` | Agent 自选报告的结构约束、逐项语义和引用规范化 |
| `backend/ai.py` | 模型适配、运行时协议、原文引用校验与一次输出纠错 |
| `backend/service.py` | 队列、输入快照、资料缓存、结果存储、过期与人工历史 |
| `agent-runtime/src/runner.ts` | Pi SDK 多轮执行、工具权限、次数及时间预算 |
| `frontend/src/components/report/` | 通用章节、段落、列表、表格、引用与缺口呈现 |
| `backend/public_documents.py` | 公开文件解析与经目录、哈希校验的采集归档复用 |

不新增按公告类别选择的业务模板。协议限制内容类型、大小、来源和执行权限；章节标题、顺序、补查目的以及停止时机由 Agent 根据资料决定。运行记录仅保存可审阅的工具活动，不保存内部思维过程。

## 结果与历史

`market_agent_v2` 表示新框架的判断语义。报告通过 `report.version` 标识结构版本。结果同时保留精简的结论与可选人工行动入口；旧格式仍能读取，不把旧文本重新解释为新报告。

明确需求必须能返回当前采购依据。潜在机会需要项目依据、推断关系、未确定内容及核实行动。无依据时允许没有机会。资料缺口分别表示原文未说明、尚未读取、读取失败或项目不适用；局部资料失败不覆盖正文与其他成功资料。

来源版本、引用片段、输入指纹、历史判断与人工选择一起保存。资料或偏好变化后旧结果标记待复核，原报告和人工选择保留；迁移本身不启动付费分析。

## 验证范围

工程验收包括后端全量测试、运行时构建与协议测试、前端构建，以及使用隔离样本的浏览器检查。样本覆盖无企业资料、仅有偏好、企业资料增强、正文充分而附件失败、建设线索、无依据机会、引用伪造、分页资料和历史报告。

工程验收证明协议、状态和展示闭环。真实模型对项目的理解、推断成立与行动价值需要真实项目审阅；离线样本不作为模型业务准确率。来源检索仅覆盖配置中的公开站点，不保证全网覆盖，也不会取得登录、登记或购买后才可读的文件。

## 真实调用后的优化（2026-10-13）

- 初始输入只提供采购摘要、条目数和文档索引；完整清单仍通过 `document_access` 按需读取，避免长清单绕过读取边界。
- 最后一轮关闭工具并生成报告；官方 DeepSeek 接口使用 JSON Output，保留低强度思考。校验纠正复用上一输出和本任务已读片段，最多三轮，不重做整套调查。
- 所有引用仍需通过原有正文、实际读取片段、关系及版本校验；一次返回多个坏引用及可复制的原文提示，不自动把改写引用当作原文接受。失败调用保留已取得的 SDK 用量。
- 相邻公告导航不进入来源证据片段；链接仍可作为候选，不能借用当前页面的关系状态。
- 自动导入只排队本次新增、实质变化或关联上下文变化的项目。历史待分析/过期报告由用户明确触发全量处理，重复导入不重启旧队列。
- 长研究来源标题在手机端换行，未提取设备词时引导查看报告，不将其表述为原文缺失。

真实项目 171、174、173、188 均已成功生成新版报告，分别覆盖专业设备、长钢材清单、注浆劳务及钻探劳务。只读浏览器验收脚本为 `qa/live_report_browser.cjs`；显式付费调用与失败输出记录脚本为 `qa/live_framework_check.py`，默认不启动模型。真实样本审阅记录位于工作区的 `资料/销售平台方案/Agent框架/代码修改报告/整框架_真实模型验证与优化_2026-10-13.md`。
