# 模块职责与渐进解耦

本约定用于管理目录和依赖。重构以现有业务行为、接口协议和数据历史为验收依据。移动代码时，先建立运行基线，再在独立 Git worktree 中改动和验证。

## 目录职责

后端根目录只保留包定义、启动入口和稳定的调查来源配置。源码按职责放入下列目录：

```text
backend/
├── __init__.py
├── main.py                  # backend.main:app
├── research_sources.json    # 保持正在运行的进程的读取路径
├── application/             # 平台编排、导入
├── analysis/                # 分析策略、报告、模型协议、规则与摘要
├── documents/               # 附件读取、片段访问、Word 转换
├── research/                # 项目调查
├── storage/                 # 数据库结构与连接
├── core/                    # 项目配置、共同基础函数
├── procurement/             # 采购事实、归一化与聚合
└── tests/                   # 回归测试
```

| 目录 | 职责 | 依赖规则 |
| --- | --- | --- |
| `backend/main.py` | HTTP 入口、应用生命周期和静态页面入口 | 调用平台应用逻辑；保留 `backend.main:app` 启动入口 |
| `backend/application/` | 应用编排、事务、导入与任务状态 | 负责获取数据并调用业务模块；纯计算逐步移出 |
| `backend/procurement/` | 采购文档归一化、事实合并、附件状态和语义指纹 | 接收数据、返回结果；不连接数据库、不下载文件、不依赖 `service.py` |
| `backend/procurement/facts.py` | 从公告正文提取明确采购事实 | 不将未核实推测写成采购事实 |
| `backend/documents/` | 公开附件读取、归档复用、片段读取权限与文档转换 | 保留来源、哈希、页码和访问限制 |
| `backend/research/` | 项目调查及历史证据 | 后续拆分其内部网络与持久化职责，保持任务授权和证据版本 |
| `backend/analysis/`、`agent-runtime/` | 分析策略、报告、规则、摘要、模型调用及 Agent 执行 | 通过已有进程协议通信；密钥不进入命令行 |
| `backend/storage/` | SQLite 结构与连接 | 数据位置仍由项目配置指定 |
| `backend/core/` | 项目路径、配置与共同基础函数 | 不依赖应用编排；不把业务职责继续堆进通用函数 |
| `frontend/src/pages/` | 页面导航、请求与用户动作编排 | 组合展示模块；不供展示模块反向导入 |
| `frontend/src/components/procurement/` | 采购信息展示与展示规则 | 通过明确的 props 接收数据；不管理页面轮询或人工决策表单 |
| `frontend/src/components/report/`、`research/` | 分析报告与项目调查展示 | 保持各自展示职责 |
| `frontend/src/utils/` | 多处调用的纯计算 | 不执行网络请求、不管理页面状态 |
| `backend/tests/` | 临时数据库和替代外部依赖的自动测试 | 不连接用户数据库或真实付费模型 |
| `qa/` | 系统、浏览器和真实来源验收工具 | 先阅读脚本副作用；真实模型验收与普通回归分开执行 |
| `docs/` | 契约、模块职责、验收与开发说明 | 不保存运行日志、截图和用户数据 |
| `data/` | 数据库、设置、密钥、日志和证据 | 运行资产；不搬迁、不提交到 Git |
| `tmp/` | 临时验证产物 | 不作为程序代码或文档的长期入口 |

根目录保留 README、依赖清单、接口约定、启动/停止/安装脚本。不要为了目录整齐搬动运行入口。`node_modules/`、`dist/`、`.venv/` 是依赖或构建产物，不放业务代码。

## 本轮范围

第一轮将采购计算从应用编排中移出，采购展示从项目详情页移出。第二轮将后端平铺源码归入职责目录，并同步迁移内部源码、测试和验收脚本的导入及替代依赖路径。

对外 HTTP 接口、`backend.main:app` 启动入口、页面文案和 DOM 保持现有契约。数据库 SQL、事务、后台调度、模型协议和真实数据路径保持现有机制。旧内部导入如 `backend.service` 改用 `backend.application.service`，不在根目录保留转发源码，也不安装全局导入钩子。包内私有函数的兼容名称继续保留。

目录归类不代表内部职责已经全部解耦。`application/service.py` 的任务执行、`research/project_research.py` 的网络与持久化、`analysis/ai.py` 的协议与校验仍需后续分别深化。

## 验证和切换

1. 确认现有服务健康、工作区改动和测试基线。
2. 在独立 worktree 开发；测试显式指定临时 `SCREENING_DB_PATH`、`SCREENING_IMPORT_PATH` 和 `SCREENING_ARCHIVE_ROOT`，禁用真实模型配置。
3. 验证采购事实、引用出处、冲突、历史快照、人工选择、过期判断、导入幂等和任务竞态。
4. 运行后端全量测试、前端类型检查与构建。采购界面使用独立预览端口及 Mock 接口进行浏览器回归。
5. 合入前逐项核对改动范围及兼容入口，先保存可恢复的源码基线。
6. 当前启动脚本未启用自动重载；合入源码不代表运行进程已切换。切换新版本前仍需验证独立新进程的启动、HTTP 契约与关闭行为，正常停止后再启动，避免同时连接真实数据库运行两套后台任务。

运行中的 Python 进程继续执行已导入的代码。整理源码目录时，不停止它、不改静态页面目录、数据库或原文归档。调查来源配置保持 `backend/research_sources.json`，因为旧进程可能在任务开始时再次读取这个文件。正常单进程重启切换版本会有短暂停机；本地平台当前没有配置保证无中断的滚动发布。

测试通过降低回归风险，不能证明任何未来改动都零故障。只有验证通过的批次继续迁移；出现回归时保留当前运行版本，修复或回退该批次源码。

## 两个系统的交接

采集系统输出 `data/export/records.jsonl`，筛选系统只读导入。字段、正文、版本、附件及归档路径是跨系统契约。采集系统内部模块拆分不改变导出文件位置；筛选系统模块拆分不改变采集定时任务和归档位置。

当前 `backend/core/config.py` 仍含本机默认采集路径。可配置路径已有环境变量与平台设置入口；将默认值改为可移植配置应另作迁移，并验证存量设置，不混入本轮职责拆分。
