# 销售平台信息采集系统

2026-10-16：日常操作已接入旁边销售平台的“信息采集”页面，可查看来源和执行历史、启停来源、立即采集及调整 Windows 每日任务。采集仍是独立模块，原 CLI、数据与归档位置保留；平台通过 `collector.control` 的 JSON 协议管理，手动与定时采集共用操作系统文件锁，繁忙时退出码为 3。平台发起的采集完成后会自动导入筛选系统。管理端不直接写采集数据库。

代码与运行数据的目录职责、兼容入口及渐进重构约定见 [模块与目录约定](docs/architecture.md)。

负责来源登记、采购公告采集、留证、字段提取、去重与版本、日报和后续 AI 数据导出。系统不计算商机价值分数，也不把新闻推测写成采购事实。

## 立即运行

在本目录的 PowerShell 中执行：

```powershell
python -m pip install -r requirements.txt
python -m collector run
python -m collector status
python -m collector export
```

运行数据保存在 `data/collector.sqlite3`，原始 HTML/PDF 在 `data/archive/`，日报在 `data/reports/YYYY-MM-DD.md`，供后续 AI 读取的 JSONL 在 `data/export/records.jsonl`。JSONL 每行包含原文、原文存档路径、内容哈希、来源、版本、结构化字段、事实摘录与带依据的待核实推测。历史公告与新闻共用记录结构，日报分栏展示。

采集开始先发布已提交的资料；之后每条公告完成入库即原子更新 JSONL，不再等整批结束。文件仍是全部记录的最新版本快照，筛选平台按 ID 增量接收。后续来源失败或进程中断时，此前发布内容保留；日报和最终关联整理仍在批次结束执行。

重生成某天日报：

```powershell
python -m collector report --date 2026-10-03
```

更新字段规则后可从保存的原文重新提取，无需再次访问网站：`python -m collector reprocess`。

单独运行一个来源：

```powershell
python -m collector run --source ccteg_materials
```

## 来源接入

### 当前采集范围（2026-10-16）

正式 `run` 流程只接收近 30 天发布的设备整机或备品备件采购公告，配置位于 `sources.json` 顶层的 `max_age_days`（正整数，默认 30）。日期按北京时间判断，包含窗口边界日；发布时间优先取列表明确日期，缺失时读取详情页明确的发布时间。缺失或无效日期不以抓取时间代替，也不进入新采集记录。

明确的投标、报价或响应文件递交截止时间已过时不采集；仅有文件获取或报名截止不能当作投标截止。只有日期而没有时刻的截止日按当日结束判断。

矿业权、集团新闻、中标／成交／候选结果、纯工程施工、设计、维修、租赁、服务及原材料需求不再进入采集库。设备名称出现在项目背景、公司名称或资格业绩中不能证明在采购设备；设备供货包含安装调试的、EPC 项目下单独采购设备的仍可保留。自然资源部两类矿业权和酒钢集团新闻来源已停用，来源配置与历史记录保留。

列表日期已明确超出窗口时，在请求详情前过滤；其余内容在详情解析后、附件下载和模型抽取前过滤。运行统计记录 `filtered` 数量，日报列出被过滤公告的标题、来源、链接和原因，便于核对误筛。历史记录与全量 JSONL 导出契约保留，升级不会清空旧数据或启动筛选平台的 Agent。

编辑 `sources.json`。每个来源需要独立 ID、名称、类别（`procurement` 或 `news`）、入口、适配器、访问状态及频率。现有 `post_json_list` 用于鞍钢、酒钢的公开搜索接口；`html_list` 使用 `item_selector`、`link_selector`、`date_selector` 和详情 `content_selector`；`rss` 读取 RSS/Atom。`allowed_hosts` 限制详情链接主机。`manual` 保留未接入来源并在日报报告覆盖缺口。公开列表如发生布局变化，采集会报错，不会把失败误报为零条新闻。

已从黄总平台只读获取 24 个来源及巡检规则，见 [platform-sources.md](platform-sources.md)。首批公开实测接入鞍钢、酒钢两家甲方平台；华润历史域名失效、现域名有安全验证，五矿和河钢在本机不可访问，均保留为覆盖缺口。中国煤科物资/工程采购是补充来源；原自然资源部矿业权与酒钢集团官网新闻来源现已按设备采购范围停用。中国政府采购网在本机返回 403、全国公共资源交易平台在本机无法通过代理连接，故处于禁用状态。详见 [source-inventory.md](source-inventory.md)。

字段按明确规则提取；缺失字段保留空值。设备和型号使用关键词及上下文规则。新闻对扩产、技改、检修、设备更新生成保守的需求推测，始终标记“待核实”并附原文摘录。可选的 AI 抽取采用 [OpenAI Responses API 结构化输出](https://developers.openai.com/api/docs/guides/structured-outputs)；只有同时设置 `OPENAI_API_KEY` 与 `OPENAI_MODEL` 才会调用。模型结果必须附能在保存正文中找到的原文片段，否则丢弃；调用失败保留规则结果并在日报标出 `ai_fallback`。当前机器未配置这两个环境变量，所以首次实采使用规则结果。

## 每日自动运行

首次确认来源和日报后，以当前用户注册 Windows 定时任务：

```powershell
.\register_daily_task.ps1 -At '07:30'
```

已注册当前用户的 Windows 定时任务，每天 07:30 本机时间运行 `run_daily.ps1`，日志写入 `data/logs/`。日报的异常栏列出失败、部分失败、解析问题、未运行来源和覆盖缺口。`data/trial-status.md` 自动记录各来源 14 天连续成功情况。系统运行至少 14 个自然日后，按实施方案抽样核对漏采、编号、截止日、重复和变更，再记录验收结果；首次运行不能代替连续试运行。

## 核心规则

- 首次抓取存一条记录和 v1 原文；相同内容哈希只刷新最近见到时间；变化会生成新版本和变更事件，旧版本保留。
- 同站同 URL 是同一记录；同站同编号、同标题和类型也归同一记录。跨站综合规范化链接、编号、采购方、标题与正文识别重复；证据不足时只标为疑似重复并分别保留。
- 更正、中标与前序公告用来源、采购方和归一化项目标题形成 `project_key` 线索；不凭模糊相似度自动合并原文。
- PDF 文本可提取；扫描版被标为 `needs_ocr`，原件仍存档并在日报报异常。该版本未内置 OCR。
- `.doc` 附件自动通过后台 LibreOffice 转换为 PDF 并提取文字、页码，`.docx` 自动提取段落和表格；存档和哈希保留原 Word 文件。Windows部署运行 `install-document-converter.ps1` 自动准备转换组件（筛选平台的安装依赖脚本也会安装）；Linux需安装LibreOffice，也可用 `LIBREOFFICE_PATH` 指定启动器。每次转换最多90秒、单批附件最多180秒，加密、损坏、超限或组件缺失会记录具体错误。
- 发布时间只从列表或详情明确的“发布时间/发布日期/公告日期”获取，不从正文任意日期推断。
